# Deep Analysis implementation

Pawn Appétit uses its existing Rust/Tauri backend, Shakmaty rules, local UCI process, SQLite store and React UI. This is an independent implementation, not a port of another application's code or storage. The desktop screen and the debug CLI share the persisted analysis core.

## Boundaries

- `src-tauri/src/chess/`: legal chess positions, PGN support, and UCI process (`uci`, `isready`, `position fen ... [moves ...]`, `go infinite`, `stop`, `quit`). `deep_analysis.rs` validates scored `info` PVs and parses `score cp`/`score mate`, depth and MultiPV. Existing option discovery and MultiPV setting are reused.
- `deep_analysis_score.rs`: white-relative `Centipawns`, signed `Mate(distance)` and `Unknown`. Mate is never converted to a centipawn. The separate tree index is the first of 100 supplied upper bounds greater than or equal to a centipawn score, or 100 beyond them; index 50 corresponds to zero centipawns. Mate and unknown have no tree index. Minimax ranks a White win by mate ahead of all centipawns and a White loss behind all centipawns; White maximizes, Black minimizes.
- `deep_analysis_scheduler.rs`: typed settings, completion policy and four candidate-selection stages. These strategies are bounded heuristics over known, legal engine-PV occurrences, not a recreation of Aquarium's candidate-generation internals.
- `deep_analysis_tree.rs`: move _occurrences_ (`MoveNode`) with parent edges and complete move histories. Equal canonical positions retain distinct move paths. Direct analysis and provisional backed-up minimax remain separate; minimax belongs to the occurrence/parent branch, not the shared position. Accepted result, PV edges and affected ancestor updates commit in one SQLite transaction.
- `deep_analysis_position.rs`: project-local `PositionRecord` identity, migration, accepted position evaluations, quality-aware result reuse and propagation to every referring occurrence. A single canonical position can have many move occurrences. Hash lookup always verifies the canonical representation.
- `deep_analysis.rs`: persisted project/task queue, scheduler cycle, conservative cache, UCI worker, Tauri progress and semantic update events, commands, and CLI entry points. Automatic mode is opt-in and does not change older manually queued projects.
- `deep_analysis_task.rs` and `deep_analysis_read.rs`: immutable queued-task execution requirements and stable UI-facing project, node, scheduler and task metadata. The React screen subscribes to the service's progress/update events and refreshes typed read models; a 15-second timer is a fallback, not the normal update path. The event-only test disables fallback timers and verifies the refresh.

## Scheduler

Cycle `1 → Random`, `2 → Alternatives`, `3 → Base or Prolong`; repeat. On every third cycle choose Prolong when `(cycle / 3) % max(1, prolongFrequency) == 0`, otherwise Base. A run of empty stages spanning a configured frequency interval exhausts an otherwise empty queue. No timer or engine is restarted on database open.

Base chooses unanalysed, known-PV occurrences near the root's backed-up centipawn index (`± maxDelta`), widens by three through an additional 52, clamps candidates to `0…99`, and limits _unique eligible positions_ to `maxPositions`. Random filters by range and samples unique positions without replacement with weight favoring indices closer to root; duplicate paths do not increase a position's probability, and seeded RNG makes the selector reproducible in tests. Alternatives first filters non-primary sibling PV moves with a meaningful analyzed parent and close score, then deduplicates by position. Prolong selects primary continuations; `prolongDepth` is a count of _position tasks_, not a UCI depth. A manual prolong can be queued for an unanalysed PV child and enters the priority lane; it does not interrupt the active task. Automatic search is bounded by `maxPly` relative to root, plus `maxPositions` per stage. Future work should make tree width and total CPU budget configurable independently.

The default automated worker uses `go infinite` and accepts a valid scored PV under the typed modes: TimeOrDepth (`time >= minimum || depth >= requested`), TimeAndDepth (`time >= minimum && depth >= requested`), Ungated (valid PV). At ten times requested time it accepts a valid PV even without depth or returns an explicit timeout with no accepted result. The worker sends `stop`, waits briefly for `bestmove`, and shuts the process down. Engine EOF, no scored PV and invalid PV fail the task rather than inventing an evaluation. `time_ms` is milliseconds, depth is plies, and the hard limit is independent of the engine's `go` arguments.

## Persistence and recovery

The separate `deep-analysis.sqlite` file holds projects, tasks, scored lines, move-occurrence tree, canonical positions, position evaluations, task-to-node interests, scheduler settings/cycle and a conservative legacy analysis cache. Migrations on `Store::open` are idempotent, preserve historical task/result rows, and do not launch an engine. Pre-position databases are backfilled transactionally from each node's stored legal FEN, preserving IDs, tree topology, accepted results, task execution snapshots, queued/running state and settings; a completed legacy analysis with unknown measured duration remains visible but cannot satisfy a time-quality claim. The task-execution insert trigger snapshots engine/profile, MultiPV, time/depth, operation and cache policy. Recovery requeues interrupted tasks, coalesces equivalent pending position searches, and leaves projects paused until explicit Resume. The latest graph migration sets `PRAGMA user_version=6`; older intermediate migrations may rewrite the version during open, so table/column inspection and transactional backfill are the durable checks.

    AnalysisTask ────────────► PositionRecord ◄──── MoveNode (path A)
       │                            ▲                      │
       └─ interested paths ─────────┼────────────── MoveNode (path B)
                                    │                      │
                         shared accepted result    separate ancestors/minimax

`deep_position_records` is project-local: `(project_id, canonical_epd, halfmove_clock)` is unique; `position_key` is an indexed Shakmaty 128-bit legal-en-passant Zobrist hash plus halfmove clock, never the sole equality check. Canonical EPD verifies placement, turn, castling and legally relevant en passant; the halfmove clock distinguishes fifty-move contexts, while fullmove number does not alter legal identity. Repetition histories can differ between equal records. Each `deep_tree_nodes.position_id` points to the record without merging the node or its complete history. `deep_position_evaluations` stores accepted task provenance, engine/profile, score, depth, time, PV and search-context key. Only FEN-only analyses are shared across move histories; history-scoped analyses remain on their original path. `deep_task_interests` records interested occurrence IDs, strategy reasons, priority and prolong count. The position/evaluation lookup, node-position, task-position-status and interest-node indexes make graph reads and deduplication bounded by lookup rather than full table scans.

A queued task can absorb an equivalent or weaker queued request for the same position; a running task accepts equivalent additional interests without restarting the engine. Stronger requirements upgrade pending work, while insufficient accepted analysis cannot satisfy a new task. A suitable accepted result is reused only when engine/profile, MultiPV, depth, elapsed time and score meet the requested snapshot. Accepted position scores update all referencing paths; every path recomputes its own ancestor chain, with White maximizing and Black minimizing, so shared static evaluation does not become a global minimax score. The older `deep_analysis_cache` remains conservative, keyed by legal FEN *and* occurrence history plus engine, MultiPV, time and depth; it is not a second position identity, and it cannot claim cross-history reuse. A move may transpose without implying a compatible search result.

On app startup recovery requeues interrupted running tasks and moves persisted `running` or `pausing` projects to `paused`. No worker is relaunched until explicit Resume. Pause after current marks the project `pausing`: the active search reaches its ordinary acceptance condition, its result/tree/minimax commit completes, then the worker pauses before claiming another task; queue and cycle remain intact. Immediate Pause signals cancellation through the active worker, stops the engine, requeues the interrupted task, and retains a depth-improving provisional PV snapshot without accepting it as completed. Stop disables generation and can retain or clear pending work without deleting accepted results. Paused and stopped projects retain their tree, cache, scheduler settings and queued tasks. The CLI `run` stops after its accepted-result budget and pauses; `show` only reads; `resume` explicitly restarts work. Reopening SQLite alone never launches Stockfish.

## Try the core

From the repository root, with local Stockfish installed:

    PATH="/opt/homebrew/opt/rustup/bin:$PATH" cargo run --manifest-path src-tauri/Cargo.toml --no-default-features --bin analysis_debug -- run "$HOME/.hermes/cache/scratch/my-analysis.sqlite" /opt/homebrew/bin/stockfish 'rnbqkbnr/pppppppp/8/8/8/8/PPPPPPPP/RNBQKBNR w KQkq - 0 1' 4 150

Copy the printed project UUID, then independently run `analysis_debug show DB PROJECT_ID` or `analysis_debug resume DB PROJECT_ID COUNT`. Do not use a user's existing app-data database for this smoke test.

Checks: `cargo test --manifest-path src-tauri/Cargo.toml --no-default-features`, `cargo fmt --manifest-path src-tauri/Cargo.toml --check`, `cargo clippy --manifest-path src-tauri/Cargo.toml --no-default-features --all-targets`, and frontend Vitest/TypeScript checks.

## Deliberate differences and remaining work

No proprietary binary resources, Delphi layouts, `.elm`/`.hsh`/`.dst` formats or `insert_best` behavior are used. The exact historic Alternatives/Random/Prolong scoring, mate index and pause path were unresolved: our tested heuristics and explicit pause semantics are deliberate independent choices. The canonical position graph is a clean-room improvement, not a claim about another application's unknown transposition internals. Move occurrences stay distinct even when they share a position. Provisional minimax does not prove an incomplete tree is solved.

Deferred beyond this milestone: terminal/draw proofs and additional engine statistics. The debug CLI remains useful for bounded recovery tests; the Rust/Tauri/React screen is the supported desktop workflow.
